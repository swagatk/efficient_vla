# Continued training of SmolVLA on LIBERO-10

Continue training the public `lerobot/smolvla_libero` checkpoint on the LIBERO-10 demonstrations with
LeRobot's own training script, then evaluate it with the protocol behind the 57.0% baseline.

## Why

- **The baseline:** `lerobot/smolvla_libero` scores 171/300 (57.0%) on LIBERO-10, init states 0-9 x seeds
  0-2, through `baseline_performance/evaluate_all.py` on Kaggle
  (`week6/smolvla_libero_lerobot_eval_kaggle/`). It matches the external LIBERO-CTRL measurement on the same
  init states (`baseline_performance/README.md`).
- **The checkpoint is under-trained:**
  - Its `train_config.json` shows 25,000 steps at batch size 32 on `lerobot/libero`, which is all four LIBERO
    suites: 1693 episodes and 273,465 frames, so about 2.9 passes over the data.
  - LIBERO-CTRL reports that this is one eighth of the SmolVLA paper's sample budget
    (`baseline_performance/reference_libero_ctrl/README.md`). The paper reports 71% on LIBERO-Long.
- **Self-generated data failed:** residual SAC and self-filtered BC trained on the policy's own rollouts and
  did not help (`week6/sac_residual_task6_pilot2/`, `week6/self_filtered_bc_task6/`). The demonstrations
  are a source of behaviour the policy has not fully learned yet.

## Hypothesis

Continued training on the LIBERO-10 demonstrations raises success on LIBERO-10, init states 0-9 x eval seeds
0-2 (300 episodes), from the base's 171/300 (57.0%) to **at least 195/300 (65%)**. The test is an exact
McNemar test paired by (task, seed, init state) against `week6/smolvla_libero_lerobot_eval_kaggle/per_episode.csv`.

- **Failure:** 171/300 or fewer. That is recorded as a negative result in `week6/`.
- **Between 172 and 194:** inconclusive. It needs more training seeds before any claim.
- **Reported checkpoint:** the final one, chosen before the run. Intermediate checkpoints are kept for
  diagnosis but are not evaluated on init states 0-9, so nothing is selected on the reported episodes.
- **Limitation:** there is one training seed, because the GPU budget is 4-5 A100 hours. Three eval seeds
  measure eval variance, not training variance.

## Method

`run_continued_training.sh` runs `lerobot-train` (lerobot commit `b6ec006`, as for every other result here).
Settings marked * differ from the checkpoint's own `train_config.json`.

| Setting | Value |
|---|---|
| Start | `lerobot/smolvla_libero@a24f1f3804`, full model (`train_expert_only=false`, as the checkpoint) |
| Data* | `lerobot/libero@a1aaacb7f6`, episodes 0-378 only: the 10 LIBERO-10 tasks (`task_index` 0-9), 379 episodes, 101,469 frames |
| Normalisation | the dataset's `meta/stats.json`, identical to the checkpoint's state and action stats (checked) |
| Batch size | 32 |
| Steps* | set by the notebook from the measured speed, so that training fits about 3 hours, at most 30,000 |
| Learning rate* | peak 5e-5 (checkpoint: 1e-4), 500 warm-up steps (checkpoint: 1000), cosine decay to 2.5e-6 over the run |
| Camera names | `image`/`image2` renamed to `camera1`/`camera2`, as the checkpoint |
| Seed* | 0 (checkpoint: 1000) |

- **Learning rate:** the lower peak is a guess. The run starts from trained weights, so a full warm-up back to
  1e-4 could undo part of what was learned. No learning rate was tuned.
- **Data volume:** the checkpoint saw about 300,000 LIBERO-10 samples (25,000 x 32 x 101,469 / 273,465).
  20,000 steps at batch 32 add 640,000, about 6.3 passes over LIBERO-10.
- **Evaluation:** `baseline_performance/kaggle_baseline_lerobot_eval.ipynb` with `CHECKPOINT = "continued"`,
  the same notebook, GPUs and settings as the 57.0% baseline (`n_action_steps=1`, 520 steps, 256x256). It
  compares with the baseline episode by episode. The baseline run took 8.2 h for 300 episodes on 2 x T4
  (`week6/smolvla_libero_lerobot_eval_kaggle/evaluate_all.runner.log`).

## How to run

1. **Train on Colab:** `colab_continued_training.ipynb`, on an A100 runtime with at least 8 GB free on Google
   Drive. It measures the speed over 100 steps, sets the step budget, trains in the background, and mirrors
   the newest checkpoint to Drive. If the runtime is lost, running the notebook again resumes from Drive.
   At the end it runs one rollout to check that the checkpoint loads.
2. **Move the checkpoint to Kaggle:**
   - Download `smolvla_libero10_continued_final/` from Drive (about 0.9 GB).
   - Upload it as a private Kaggle dataset.
   - Add the dataset as input to the baseline notebook.
3. **Evaluate on Kaggle:** set `CHECKPOINT = "continued"` and use Save & Run All.

The notebook is generated by `build_colab_notebook.py`. Edit the builder, not the notebook. It takes the
environment cell verbatim from the Kaggle baseline notebook, so both install the same stack.

## Files

- `run_continued_training.sh`: the exact `lerobot-train` command (`SMOKE=1` for 4 steps on 2 episodes;
  `RESUME=1`; `SYNC_DIR` for the Drive mirror).
- `build_colab_notebook.py` -> `colab_continued_training.ipynb`.

## Status

Code written and smoke-tested locally (October 2026), on lerobot `b6ec006` and an RTX 4090 laptop GPU shared
with another job. These runs are functional checks, not results:

- **Training:** `SMOKE=1` ran 4 steps at batch 2 on episodes 0-1 (498 frames, 393M trainable parameters,
  4.2 GB peak). Checkpoints were saved and mirrored.
- **Checkpoint check:** after 4 steps, 414 of the 500 weight tensors had changed. The state and action
  normaliser stats were identical to the base checkpoint's, and the saved config uses the camera names
  `camera1` and `camera2`.
- **Resume:** with the local folder deleted, `RESUME=1` restored the checkpoint from the mirror and resumed
  at step 4.
- **Rollout:** one rollout of the 4-step checkpoint through `evaluate_all.py` (task 3, seed 0, init state 0,
  `n_action_steps=1`) succeeded.
