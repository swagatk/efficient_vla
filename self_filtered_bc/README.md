# Self-filtered behaviour cloning (task 6)

Fine-tune SmolVLA's action expert with LoRA on the base policy's own **successful** rollouts, using SmolVLA's
own flow-matching loss. This replaces the critic of residual SAC, which failed twice on task 6
(`week6/sac_residual_task6_pilot1/`, `week6/sac_residual_task6_pilot2/`), with outcome filtering.

## Hypothesis

The base policy is stochastic per episode: on held-out init states 0-9 x eval seeds 0-2 it solves task 6 in
15/30 episodes, and 6 of the 10 init states succeed under some seeds and fail under others
(`week6/sac_residual_task6_pilot1/eval_base/per_episode_base.csv`). Cloning only the successful rollouts from
training init states 10-49 should shift the policy toward the behaviour that succeeds.

- **Expected:** held-out success at least 21/30 per training seed (+20 points over the base's 15/30) with
  the LoRA adapter, and a positive pooled paired difference over 3 training seeds (exact McNemar test).
- **Failure:** pooled success at or below the base's (45/90), or significantly below it. That is recorded
  as a negative result in `week6/`.
- **Control:** the same fine-tune on as many episodes drawn without regard to outcome (`--selection
  all_matched`). If the control gains as much, the gain comes from extra task-6 data, not from filtering.

## Method

- **Collect** (`--stage collect`): the frozen base (`lerobot/smolvla_libero`, `n_action_steps=1`) runs on
  training init states 10-49 x collection seeds 0-2 (120 episodes) through `vla_core`, with soft resets. The
  LIBERO-CTRL reference solves 16/40 of these init states
  (`baseline_performance/reference_libero_ctrl/smolvla_libero_10_clean.csv`), so expect roughly 40-50
  successful episodes. Each episode stores the images and state exactly as the policy saw them (every
  `--frame_stride` steps) and every executed action (`rollout_data.py`).
- **Train** (`--stage train`): the target of each stored frame is the next 50 executed actions, padded and
  masked past the end of the episode. LoRA (rank 16, alpha 32) is applied to all seven projections of the
  action expert. Only the LoRA matrices train (`--train_action_heads 0`), so step 0 is exactly the base policy.
  Fixed step budget, AdamW, warm-up and cosine decay. The validation loss uses successful episodes from
  held-out *training* init states (`--val_init_states`; 45-49 in the runner, so training uses 10-44). Hyperparameters are chosen on those episodes, never
  on init states 0-9.
- **Evaluate** (`--stage eval`): deterministic seeds per (seed, init state) from `vla_core.evaluation`, hard
  resets, init states 0-9 x seeds 0-2. The comparison is paired with the base episodes of the residual-SAC
  harness check (copy `per_episode_base.csv` into the eval folder, or run `--eval_policies base,lora`).

Order of work (CLAUDE.md): CPU tests (`tests/test_self_filtered_bc.py`), then a smoke run (2 episodes,
a few training steps, 1 evaluation episode), then the task-6 pilot with one training seed, then 3 seeds plus
the control. Other tasks, or a second round of collection with the fine-tuned policy, come only after a
positive task-6 result.

## Review of `supervised_task_specific_lora_adapters/` (October 2026)

That folder fine-tuned LoRA on the LIBERO demonstrations. It was abandoned in September after a task-1
evaluation scored 0/30 (gitignored `outputs/eval_results_task1/`). The review found that the evaluation
could not have measured LoRA:

- **Evaluation harness (invalid):**
  - `eval_lora_policy.py` wrapped `mujoco.mj_fullM` a second time on top of `robosuite_mujoco_patch`, which
    is FAIL-007 (wrong OSC mass matrix; it gave the base policy 0/10 in the hybrid harness).
  - It built its own `OffScreenRenderEnv` pipeline and never seeded the environment.
  - It was never checked against the base policy's 11/30 on task 1 (`baseline_performance/results_300926/`).
  - The script is now retired (refuses to run). The invariant checker scans every tracked file for
    `mj_fullM` re-patching, not only the repo root and `hybrid_diffusion/` as before.
- **Training (`train_supervised_lora.py`; not used here, but its weak points are avoided):**
  - Inputs are the original LIBERO HDF5 demonstrations at 128x128 upsampled to 256, whereas the policy sees
    256x256 renders. Self-collected rollouts store exactly what the policy saw.
  - It uses the older `HuggingFaceVLA/smolvla_libero` checkpoint.
  - It has no `--seed`.
  - Resuming restarts the learning-rate schedule.
  - It fully fine-tunes the action heads by default.
  - It replaces LeRobot's `apply_rope`: identical in float32, and differs by up to one bfloat16 rounding step
    under autocast.
- **Training (correct):** the axis-angle state (`ee_ori` is `quat2axisangle` in LIBERO's `create_dataset.py`),
  the 180-degree image rotation for the OpenGL image convention, the per-demo validation split and the
  pad-mask key all match LeRobot.

## Status

**Negative result on task 6 (October 2026):** pooled over 3 training seeds the method scored 46/90 against
the base's 45/90 (19, 13 and 14 of 30 per seed); the unfiltered control scored 29/90, worse than both.
Numbers, tests and interpretation: `week6/self_filtered_bc_task6/README.md`.

Code and CPU tests written (October 2026). Local smoke run (`SMOKE=1`, shared GPU and CPU, low priority)
completed every stage. The runs are functional checks, not results:

- **Collect:** 2 episodes (init states 10-11, both failed at 520 steps), about 530 s each on the shared
  machine. About 46 MB per failed episode at `--frame_stride 2`, so 120 episodes need roughly 5 GB.
- **Train:** 5 steps.
- **Evaluate:** base 0/1 and LoRA 1/1 on seed 0, init state 0. The base episode matches the pilot-1 harness
  check (failure at 520 steps). The largest LoRA weight after 5 warm-up steps was 7e-6, yet the outcome
  flipped, another sign that task-6 episodes flip under tiny perturbations.

Loss check on 5 stored frames, with fixed noise and times:

- Flow-matching loss against a chunk the policy samples from the same training batch: 0.04, so the training
  inputs match what the policy sees at inference.
- Loss against the stored executed actions: 1.84. The executed actions come from 50 separate replans along
  the closed-loop trajectory, and they diverge from any single predicted chunk after the first few steps
  (the first actions match closely).
- The base weights are bfloat16; the LoRA weights are float32 (PEFT up-casts them).
